## 规范定位

它是一套 **纯 Python 流程脚手架**（流程脚手架规范 V1.0），适合用 Python 写自动化数据流程：从各数据源（飞书多维表格、快递100 等 API）取数 → 处理 → 回写 → 飞书通知 → 定时跑。典型产物形如：

```
{桌面上的流程文件夹}/
├── 主流程.py                # 入口：固定顺序调用 A→B→C
├── 流程A_{数据源-用途}.py
├── 流程B_{数据源-用途}.py
├── 通知.py                  # 飞书通知（失败到群 / 成功回复）
├── 运行记录.py              # 运行结果写飞书多维表格
├── 临时/                    # 中间文件（每次覆盖）
├── logs/                    # 日志（最多 10 个，旧自动删）
└── run.bat                  # 手动双击运行入口
```

## 硬性规则亮点

| 维度 | 规则 |
|------|------|
| 生成行为 | 用户给参考脚本+口头描述即可，AI **禁止反问细节**，自己拆流程、建目录、直接交付验证通过的代码 |
| 命名 | 变量**一律中文命名** + 类型注解（`日期列表: list = []`），函数与**每一行代码**都要中文注释 |
| 调度 | AI 自动搭 Windows 计划任务，**每小时执行一次**（DailyTrigger + Repetition），独立 Python 直连主流程，不经 cmd 中转 |
| 防并发 | `.running.lock` 文件锁 + **PID 存活检测**，进程被强杀后下次自动清死锁继续跑 |
| 通知/记录 | 飞书失败通知群、成功回复指定消息；运行结果每日去重写入飞书多维表格（当天成功记录用 PUT 覆盖，失败记录新建） |
| 健壮性 | 所有 HTTP 请求显式 timeout；Token 缓存+提前 5 分钟自动刷新；外部 API 重试 3 次，慢接口禁止无意义重试 |
| 验证 | 生成后必须实际跑通：空跑 → `--limit N` 小样本联调 → 失败路径 → 日志 → 定时任务 → 锁机制，全部通过才交付 |

## 和影刀路线的区别

- **python-app-standard**：纯 Python + Windows 计划任务调度，无界面，靠 API/requests 干活，适合**后端数据流程**（取数、回写、通知）。
- **影刀 RPA（shadowbot-cli）**：用影刀流程文件跑，能操作**有界面的系统**（网页点击、Excel、桌面软件），和 yoonup 的 web-js 技能（逆向接口+JS）更互补。

所以关键还是看你那条自动化流程长什么样：
- 全是**接口/数据流转、无界面** → python-app-standard 最合适；
- 要**操作网页/桌面软件界面** → 走影刀；
- **界面操作 + 数据回写混合** → 可考虑两者结合（影刀触发，Python 处理）。

## 核心限制

Hermes 是 Python/Rust 混合项目，依赖 Linux 环境，**不能做成 .exe 双击即用**。但"打包成压缩包、拖过去解压直接用"这件事，用 **WSL2 子系统快照**可以实现。

| | 方案 A：WSL2 快照导出 | 方案 B：Docker Compose |
|---|---|---|
| 原理 | 装好 Hermes 的整个 WSL 子系统导出为 `.tar.gz`，目标电脑 `wsl --import` 还原 | 官方 Docker 镜像 `nousresearch/hermes-agent` + compose 编排 |

| 前提 | 目标电脑开启 WSL2 + 虚拟化 | 目标电脑装好 Docker |

| 离线可用 | ✅ 完全离线 | ✅ 完全离线（镜像本地已存在） |

**安装器做的事**（全自动，零依赖要求）：

- 把 `hermes` 加入当前用户的 PATH

**功能支持度**（原生 vs WSL2 对比）：

| 功能 | 原生 Windows | WSL2 |
|------|:---:|:---:|
| CLI / TUI / gateway（15+ 平台） | ✅ | ✅ |
| Cron 定时任务 | ✅ | ✅ |
| 浏览器工具（Chromium） | ✅ | ✅ |

| 本地模型（Ollama/LM Studio） | ✅ | ✅ |
| Web 仪表盘 | ✅ | ✅ |
| 仪表盘嵌入式终端面板 | ❌（缺 POSIX PTY） | ✅ |
| 登录自启动 | ✅（计划任务） | ✅（systemd） |

**唯一缺的**是仪表盘里嵌终端那个标签页，核心功能全部原生可用。

## 这对你"打包解压即用"需求的意义

原生安装天然就是**自包含目录结构**，便携打包思路变得非常简单：

```
联网电脑：安装 → 配置好 model → 打包 %LOCALAPPDATA%\hermes\ 整个目录
目标电脑：解压到 %LOCALAPPDATA%\hermes\ → 写个启动 bat（临时加 PATH）→ 敲 hermes 直接用
```

不需要 WSL 镜像那种几个 GB 的块头，目录本身轻量；配合一个 `启动.bat` 设置 `PATH` 和 `HERMES_GIT_BASH_PATH`，就能做到"拖过去解压即用、不污染系统"。

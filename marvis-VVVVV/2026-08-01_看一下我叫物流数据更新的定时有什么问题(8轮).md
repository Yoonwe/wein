## 代码层面的 4 个缺陷（按严重程度）

1. **并发运行冲突（首要原因）**：几乎每份日志都出现两套交错记录，证明任务计划在同时运行多个实例（或与手动运行重叠）。
   - 日志文件名只精确到秒 `%Y-%m-%d %H-%M-%S`，同秒启动的实例共用同一日志文件，互相混写。
   - 临时文件全部使用固定名（`流程A_飞书-查询.json` 等），实例间互相覆盖 → 触发 JSONDecodeError。
   - `clean_old_logs()` 的 `os.remove` 无任何容错 → 并发下必现 FileNotFoundError / PermissionError。

2. **`clean_old_logs()` 缺少异常保护**：`os.remove` 裸调用，任何删除失败直接中断整个主流程（最近两次失败均由此触发）。

3. **流程间依赖固定文件名**：A→B→C→D 通过硬编码 JSON 文件名传递数据，无实例隔离（如进程ID/时间戳后缀），并发时必然互相污染。

4. **流程D 依赖 `_strptime` 环境脆弱**：`dt.strptime` 在部分 Python 环境（如 3.14 或精简 runtime）报 `No module named '_strptime'`，且该异常未被局部捕获，直接冒泡到主流程。

- 通知失败仅写日志，不改变退出码。

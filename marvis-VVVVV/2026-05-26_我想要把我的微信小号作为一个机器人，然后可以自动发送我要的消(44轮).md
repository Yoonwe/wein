### [AI · 2026-05-26 15:21:52]

市面上常见的个人微信号群管理机器人，核心实现方式主要有以下几种：

## 1. 基于 itchat / WeChaty 等开源框架（已基本失效）

早期最流行的方案。原理是通过 Web 微信协议模拟登录，收发消息。

- **itchat**（Python）：扫码登录网页版微信，通过 API 收发消息、获取群列表、@人、踢人等
- **WeChaty**（Node.js/多语言）：更强大的跨平台微信机器人框架

**现状**：微信从 2019 年起逐步封杀 Web 微信接口，大部分新注册微信号已无法使用网页版微信，这条路基本走不通了。

## 2. 基于 Hook 注入（目前主流，但有风险）

通过注入微信进程，拦截和调用微信内部函数来实现自动化。

| 框架 | 语言 | 特点 |
|------|------|------|
| **千寻** | C++/易语言 | 老牌框架，功能全面 |
| **可爱猫** | 易语言/HTTP | 提供 HTTP API，上手简单 |
| **VLW** | C++ | 较新，稳定性好 |
| **Sunny 微信机器人** | C# | 开源，社区活跃 |

**原理**：注入一个 DLL 到微信进程，Hook 微信的消息收发函数，拦截消息并可以主动调用发送函数。

**风险**：
- 微信会检测异常注入，**有封号风险**
- 微信版本更新后框架可能失效，需要等框架作者适配
- 部分框架需要付费

## 3. 基于 UI 自动化（最安全但最笨）

通过模拟鼠标键盘操作来控制微信客户端，不涉及任何注入或协议破解。

- **uiautomation**（Python）：通过 Windows UI 自动化接口操控微信窗口
- **pyautogui + pywinauto**：模拟键鼠操作

**优点**：完全合规，不封号
**缺点**：速度慢、不稳定、不能后台运行、不能多开

## 4. 基于 ADB 操控安卓模拟器

在电脑上开安卓模拟器装微信，通过 ADB 指令模拟点击滑动。

**优点**：比 PC 端 UI 自动化更稳定，可以后台运行
**缺点**：需要模拟器环境，延迟较高

---

## 总结

目前市面上那些"个人微信号群管理机器人"，绝大多数用的是**第 2 种 Hook 注入方案**。这类方案功能最强，但本质上是灰色地带，微信官方一直在打击。

如果你只是想实现简单的自动发消息功能，我可以帮你用**方案 3（UI 自动化）**或**方案 4（ADB 模拟器）**来实现，虽然笨一点但安全合规。需要的话告诉我具体需求。

## 待机状态分析

| 状态 | 对微信/脚本的影响 |
|------|------------------|

| **休眠**（S4） | 内存写入硬盘后关机，微信完全关闭，脚本停止运行 |
| **混合睡眠** | 先睡眠，电量不足时自动转休眠，同样无法运行 |
| **屏幕关闭** | 微信和脚本正常，能接收消息 |

- 电源选项 → 更改计划设置 → 使计算机进入睡眠状态 → 从不
- 关闭显示器时间可以设短一点（如 5 分钟）

| 类型 | 主动推送 | 群发 | 收到位置 | @ | 免打扰 |
|------|---------|------|---------|---|--------|
| 订阅号 | 每天1次 | 所有关注者 | 折叠到"订阅号"文件夹 | ❌ 不支持 | ✅ 默认折叠免打扰 |
| 服务号 | 每月4次 | 所有关注者 | 直接出现在聊天列表 | ❌ 不支持 | ❌ 不折叠 |
| 客服消息 | 不限（48H窗口内） | 仅交互过的单个用户 | 聊天列表 | ❌ 不支持 | ❌ 不折叠 |

**核心问题**：公众号**不能发消息给群聊**，只能发给个人。也不能 @。

**结论**：微信公众平台的 API 不适合你的场景（往群聊发消息）。只有这两种路：

1. **UI 自动化** — 不稳定但能往任意群发消息，你现在的方案
2. **钉钉/飞书 Webhook** — 稳定可靠，但需要用钉钉或飞书群

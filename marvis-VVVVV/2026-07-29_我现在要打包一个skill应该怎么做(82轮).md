打包一个 skill 主要分以下几步：

**1. 准备 manifest 文件（必填）**
在 skill 目录下创建 `manifest.json`，包含基本信息：

```json
{
  "name": "my-skill",
  "display_name": "我的技能",
  "description": "技能的简短描述",
  "version": "1.0.0",
  "author": "你的名字",
  "type": "skill",
  "prompt": "技能加载后给 Agent 的指令内容",
  "entry": "main.py"
}
```

关键字段：
- **prompt**：Agent 加载该 skill 时注入的指令，写清楚 Agent 该怎么做、有什么约束
- **entry**：技能代码入口文件（如果有代码逻辑的话）

**2. 编写技能代码（可选）**
如果 skill 需要执行 Python 逻辑，在 `main.py`（或 manifest 中 entry 指定的文件）里实现。框架会自动把 skill 目录加入 `PYTHONPATH`，你可以在代码里 import 项目内其他模块。

**3. 打包成 zip**
将整个 skill 目录打包为 zip 文件，确保 manifest.json 在 zip 根目录下。

**4. 安装方式**
- **本地安装**：在 Marvis 的 Skill 管理页面直接导入 zip
- **发布到 ClawdHub（可选）**：上传到技能市场供其他人安装

**5. 验证**
安装后给 Agent 发一条触发该 skill 的指令，确认 prompt 和代码是否正常执行。

## 调用规则

- **拆分维度**：按数据源/外部接口拆分，每个独立接口一个子流程；通知、写入等操作也各自独立为子流程
- **调用顺序**：主流程固定按 A→B→C……依次调用
- **调用方式**：统一使用 **函数调用**。每个子流程暴露 `run()` 函数，主流程通过 import 调用，**不使用 subprocess**。异常直接向上传导，主流程捕获后走错误处理逻辑
- **统一入口函数签名**：

```python
def run(tmp_dir: str, prev_file: str = None) -> dict:

    tmp_dir: 临时/ 目录的绝对路径
```

- **运行环境**：使用**生产环境真实凭证**运行，不做测试/沙箱隔离。运行验证时会产生真实外部副作用（飞书通知到真实群、写入生产表格）

```powershell
$svc = New-Object -ComObject 'Schedule.Service'

$task.RegistrationInfo.Description = '流程脚手架定时执行'

$trigger = $task.Triggers.Create(6)   # 6 = DailyTrigger，配合间隔实现每小时
$trigger.StartBoundary = '2026-08-01T00:00:00'
$trigger.Repetition.Interval = 'PT1H' # 每小时重复一次

$action = $task.Actions.Create(0)     # 0 = Execute

$action.Arguments = "`"C:\Users\EDY\Desktop\流程根目录\主流程.py`""
```

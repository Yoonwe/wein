---

## 一、选赛道：先确定你要做什么

| 类型 | 特点 | 推荐方案 |
|------|------|----------|
| 纯工具类（计算器、清单..） | 逻辑简单，适合练手 | Claude/ChatGPT + Cursor 直接写原生 App |
| 内容展示类（资讯、博客..） | 展示为主，无复杂交互 | AI 生成 H5，套壳 WebView 打包 App |
| 聊天/社区/电商 | 有后端、数据库、登录支付 | 前端 AI 生成 + 后端用 Supabase/Firebase |
| AI 应用（对话、生图..） | 核心是调 API | 前端 AI 生成 + 自建或云函数对接模型 |

---

## 二、选技术方案

**三种主流路线：**

### 路线 A：React Native + Expo（推荐新人）
- 一套代码跑 iOS + Android
- Expo 生态成熟，热更新方便
- AI 工具（Cursor/Windsurf/Copilot）对 RN 支持最好

### 路线 B：Flutter
- Google 出品，性能更接近原生
- 适合对 UI 动画、复杂交互要求高的场景
- 学习曲线稍陡，但 AI 也能辅助生成

### 路线 C：Tauri + React（桌面优先或轻量移动端）
- 如果要同时覆盖桌面端，Tauri 体积极小
- 移动端目前不如 RN/Flutter 成熟

---

## 三、实际开发流程

```
想法 → AI 出 PRD/原型 → AI 生成代码骨架 →
人工调试润色 → 接后端/API → 打包测试 → 上架
```

### 1. 产品定义阶段
用 ChatGPT / Claude 把想法变成结构化的 PRD：
- 用户故事
- 页面清单和导航结构
- 数据流和 API 设计

### 2. UI 设计阶段
- **Figma + AI 插件**：用 v0 / Galileo AI / Uizard 从文字描述直接生成 UI
- 或者直接用 **v0.dev**（Vercel 出品）生成 React 组件代码 + 预览

### 3. 编码阶段
- **Cursor / Windsurf / GitHub Copilot**：在 IDE 里直接对话生成代码
- **Bolt.new / Lovable**：在线 AI 全栈生成器，适合快速原型
- 核心策略：先让 AI 出 MVP，再逐步迭代

### 4. 后端阶段
- 简单场景：**Supabase**（数据库 + 认证 + 实时）或 **Firebase**
- 需要自定义逻辑：用 AI 生成 **FastAPI / Next.js API Routes** 代码
- AI 功能：直接调 OpenAI / Claude API，或部署开源模型

### 5. 打包上架
- **EAS Build**（Expo 体系）：一行命令出 iOS / Android 包
- **App Store**：需要开发者账号（$99/年），审核较严
- **Google Play**：一次性 $25，审核更宽松

---

## 四、关键注意事项

1. **从最简单版本开始**：第一版只做核心功能，不要追求完美
2. **先用 Web 验证**：AI 生成代码后先在浏览器跑通，再打包 App
3. **图标和截图不要省**：上架时最容易被拒的是元数据问题
4. **登录/支付用现成方案**：Supabase Auth / Stripe，不要自己造轮子
5. **尊重版权和隐私**：AI 生成的图片/代码需核实版权，隐私政策是上架硬门槛

## 一、数据层：飞书多维表格作为"数据库"

飞书多维表格本身就是结构化的，天然适合做仪表盘数据源：

- **免费额度**：飞书开放 API 有每月免费调用量
- **实时性**：不需要自建数据库，表格更新即数据更新
- **多人协作**：运营/业务人员可以直接在表格里改数据，仪表盘自动刷新

你需要做的：在飞书开发者后台创建一个应用，开通"多维表格"权限，拿到 `app_id` 和 `app_secret`。

---

## 二、后端：FastAPI 做同步中间层

不建议前端直接调飞书 API，原因是需要保护 token 和做数据加工。推荐结构：

```
/api/dashboard/overview    → 汇总卡片（总数/环比/趋势）
/api/dashboard/charts      → 图表数据（按维度聚合）
/api/dashboard/records     → 明细列表（分页查询）
/api/sync/trigger          → 手动触发同步
```

### 先跑通的关键：模拟数据模式

在正式对接飞书 API 之前，后端内置一套 `mock` 模式：

```python
# config.py
DATASOURCE = "mock"  # "mock" | "feishu"

# mock_data.py  直接返回写死的 JSON
# feishu_service.py  调真实 API
```

这样你可以在 **10 分钟内** 看到仪表盘跑起来的效果，确认布局和图表没问题后，再切到真实飞书数据。切换只需改一个配置项。

---

## 三、前端：响应式仪表盘

推荐 **React + ECharts / Recharts + Tailwind CSS**，原因：

- 组件化天然匹配仪表盘的卡片式布局
- ECharts 图表类型全，中文友好
- Tailwind 做响应式方便，手机上自动变成单列

典型页面结构：

| 区域 | 内容 |
|------|------|
| 顶部 | 核心指标卡片（总数、环比、达成率） |
| 中部 | 趋势图 / 柱状图 / 饼图 |
| 底部 | 明细表格，支持筛选排序 |
| 侧边 | 时间筛选器、维度切换 |

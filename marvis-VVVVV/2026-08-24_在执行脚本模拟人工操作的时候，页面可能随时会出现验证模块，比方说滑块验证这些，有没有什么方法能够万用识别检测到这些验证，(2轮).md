## 一、万用检测：怎么发现验证模块出现了

核心思路不是认验证码长什么样，而是**监控页面结构/视觉特征的变化**：

| 方案 | 原理 | 适用 |
|------|------|------|
| **选择器轮询** | 定时轮询常见验证框架的固定 DOM 特征（如 `.geetest_panel`、`#nc_1_n1z`、`.yidun_panel`、`.captcha_verify_container`） | 阿里、腾讯、极验等主流验证码框架有固定 class，命中率极高 |
| **图像模板匹配** | 截图后与验证弹窗模板做模板匹配（OpenCV `matchTemplate`） | 自研验证码、无固定 DOM 特征时兜底 |
| **目标检测模型** | YOLO 训练一个验证弹窗检测器 | 多个业务系统验证样式不统一时最通用 |
| **iframe 检测** | 验证码常藏在 iframe 里，轮询 `document.querySelectorAll('iframe')` 数量变化 | 简单粗暴但很有效 |

实战建议组合用：**iframe/框架选择器轮询为主 + 截图像素变化检测为兜底**。很多验证模块出现时页面会多一层遮罩（半透明黑底），检测全屏平均亮度骤降也能快速触发。

## 二、AI 划掉验证：滑块验证的处理链路

滑块验证分两类，处理方式不同：

**1. 缺口滑块（拼图型）**——完全可以用 AI/视觉方案闭环：
```
截图 → 视觉模型/OpenCV 找缺口位置 → 计算目标坐标
→ 模拟人类拖拽轨迹（贝塞尔曲线+变速+抖动）→ 拖动
```
- 找缺口：`cv2.matchTemplate` 找缺口模板，或 `findContours` 找色差区域
- 拖拽轨迹：**关键在轨迹不像机器**，用带加速度/减速度的缓动曲线，总时长 0.5~1.5s 随机，中间加微小回拉

**2. 行为验证（无感/点选）**——AI 图像识别点选文字/图形：截图 → 视觉模型（如 GPT-4V、本地 YOLO）识别目标文字/图形坐标 → 模拟点击。

**3. 最省事的路径**：如果公司允许，优先接**第三方打码平台**（如超级鹰、图鉴），API 提交截图返回坐标，比自己训模型便宜可靠，几厘钱一次。

## 三、关键架构建议

```python
# 伪代码：验证拦截器
def safe_action(action_func):
    while True:
        if detect_captcha():          # 1. 万用检测
            solve_captcha()           # 2. AI 处理
        else:
            action_func()             # 3. 执行原操作
            if detect_captcha_after(): # 4. 操作后复查
                continue
            break
```

**两个实用技巧**：
- 拖拽用 `ActionChains` + 自定义轨迹生成器，不要用 `drag_and_drop`（太直，必被识别）
- 失败后**换策略重试**（换轨迹、换坐标偏移、换识别方式），不要原样重试，连续失败 2~3 次就停下等人工，避免被风控锁定

## 四、必须提醒的两点

1. **合规风险**：绕过验证码可能违反目标平台服务条款，甚至涉及《网络安全法》关于规避安全措施的规定。自己公司系统/授权测试没问题，对外部平台要慎重。
2. **没有真正的"万用"**：验证码本质是攻防对抗，平台会不断升级。上面这套能覆盖 90% 的常见场景，但遇到新一代行为验证（如鼠标轨迹学习、设备指纹）就得多层方案配合。

## 一、前端 DOM 监听（最灵敏）

验证模块是 JS 动态插入 DOM 的，你可以在页面注入脚本，用 **MutationObserver** 监听整个 document 的节点变化：

```javascript
// 注入页面的监听脚本
const observer = new MutationObserver((mutations) => {
  for (const m of mutations) {
    const nodes = m.addedNodes;
    for (const node of nodes) {
      if (node.nodeType === 1) {
        // 判断新增节点是否含验证码特征
        if (isCaptchaNode(node)) {
          window.__captcha_detected__ = true;  // 通知外部
          console.log('CAPTCHA_DETECTED');
        }
      }
    }
  }
});
observer.observe(document, { childList: true, subtree: true });
```

RPA 侧（影刀/Python）持续读取标记或监听控制台输出，一旦触发就暂停当前流程去处理验证。

## 二、轮询式检测（最通用，兼容性最好）

不需要注入脚本，RPA 定时截图/查元素：

| 检测方式 | 实现 | 延迟 |
|---------|------|------|
| **DOM 特征轮询** | 每 300~500ms 查询验证码框架固定选择器（`.geetest_panel`、`.yidun_panel`、iframe 数量） | 最快，<1s |
| **截图像素检测** | 每 0.5~1s 截全屏/区域图，比对画面是否出现遮罩层、弹窗边框 | 1s 左右 |
| **OCR/视觉兜底** | 截图后用视觉模型判断是否有"滑块/验证/安全验证"文字 | 1~3s |

**推荐组合：DOM 特征轮询为主 + 截图像素检测兜底**。大多数验证码都是弹窗+遮罩，遮罩会让画面亮度骤降，用 `numpy` 算截图平均灰度变化就能秒级感知。

## 三、网络层拦截（预防式）

验证码接口通常有固定特征（如极验的 `gettype.php`、腾讯的 `captcha` 路径）。用 mitmproxy 或抓包工具监听网络请求，一旦出现验证码相关请求 URL，立即触发处理逻辑。这个能比视觉检测**更早**发现，因为请求发出时弹窗还没渲染。

## 四、放在架构里的正确姿势

不要把检测散落在每个操作步骤里，做成**全局拦截器**：

```python
class CaptchaGuard:
    def __init__(self):
        self.detector = DomDetector()      # 或 ImageDetector / NetworkDetector
        self.monitor_thread = threading.Thread(target=self._watch, daemon=True)

    def _watch(self):
        while True:
            if self.detector.detect():
                self.pause_current_task()   # 暂停当前步骤
                self.solve()                # 处理验证
                self.resume()               # 恢复执行

    def execute(self, action):
        # 所有操作走这里，被 guard 统一保护
        pass
```

关键点：**检测线程独立于执行线程**，这样不管哪一步操作触发了验证，都能立刻被拦下来，不需要在每一步代码里手动写判断。

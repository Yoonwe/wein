Obsidian 搭配 GitHub 的核心思路：**用 Git 管理 Obsidian Vault，用 GitHub 做远程仓库和跨设备同步**。以下是完整方案。

---

## 一、基础配置

### 1. 初始化 Git 仓库

在 Vault 根目录（即 `.obsidian` 文件夹所在目录）打开终端：

```bash
git init
git add .
git commit -m "init vault"
```

### 2. 推送到 GitHub

```bash
git remote add origin https://github.com/你的用户名/仓库名.git
git branch -M main
git push -u origin main
```

---

## 二、核心插件：Obsidian Git

这是社区插件，不要手动 `git add/commit/push`，让插件自动化。

安装路径：**设置 → 第三方插件 → 社区插件 → 搜索 "Obsidian Git" → 安装并启用**

### 推荐配置

| 设置项 | 建议值 | 说明 |
|--------|--------|------|
| Auto Backup | 开启 | 定时自动提交 |
| Auto Backup Interval | 30 分钟 | 自动 commit/push 间隔 |
| Auto Pull Interval | 5-10 分钟 | 多设备时拉取远程更新 |
| Pull on Startup | 开启 | 打开 Obsidian 时自动拉取 |
| Commit message | `Auto backup: {{date}}` | 提交信息模板 |
| Pull before push | 开启 | push 前先 pull，减少冲突 |

---

## 三、多设备同步流程

```
设备A 编辑笔记
    ↓（自动 commit + push）
  GitHub
    ↓（设备B 打开 Obsidian 时自动 pull）
设备B 获得最新内容
```

**关键操作习惯**：
1. 切换设备前，确认当前设备已 push（可手动 `Ctrl+P → Obsidian Git: Commit and push`）
2. 打开新设备时等插件自动 pull 完成再编辑
3. 如果出现冲突，Git 对纯 Markdown 文本的冲突解决很简单，在冲突标记中选择保留版本即可

---

## 四、`.gitignore` 推荐

```gitignore
# Obsidian 工作区配置（多设备建议忽略，每台设备独立）
.obsidian/workspace.json
.obsidian/workspace-mobile.json

# 插件缓存
.obsidian/plugins/*/node_modules

# 系统文件
.DS_Store
Thumbs.db

# 如有二进制文件
*.pdf
*.png
*.jpg
```

> `.obsidian` 文件夹本身**不要整个忽略**，否则插件列表、主题、快捷键配置都无法同步。

## 使用 GitHub Desktop 时 Obsidian 怎么配合

既然有 GitHub Desktop 就不用 Obsidian Git 插件了，流程更直观：

1. **手动 commit + push**：编辑完笔记后在 GitHub Desktop 里提交并推送
2. **手动 pull**：打开 Obsidian 前先在 GitHub Desktop 拉取最新
3. 插件可以不开（或卸载），避免两边同时操作产生锁冲突

GitHub Desktop 的好处是冲突可视化更好、不需要记 git 命令；代价是做不到 Obsidian Git 那样的定时自动备份。

核心思路：**将 `FIND`（只找第一个）改为 `SPLIT`（按商品代码切分）+ `SLICE`（跳过第一段）**，这样无论出现几次都能捕获每次后面的数字。

修改后的公式：

```formula
[物料映射勿动].FILTER(CurrentValue.[日期] >= TODAY() - 91)
  .[物料详情]
  .LISTCOMBINE()
  .UNIQUE()
  .MAP(
    CurrentValue.SPLIT(SUBSTITUTE([商品代码], " ", ""))
    .SLICE(1)
    .MAP(
      VALUE(REGEXEXTRACT(CurrentValue, "^\d+"))
    ).SUM()
  ).SUM()
```

**改动说明**：

| 原来 | 现在 | 原因 |
|---|---|---|
| `FIND(...)` 定位第一次出现位置后用 `MID` 截取 | `SPLIT(商品代码)` 按商品代码把整段物料详情切成多段 | `FIND` 只匹配首次出现，`SPLIT` 天然切割所有出现位置 |
| 直接取匹配结果 | `.SLICE(1)` 跳过第一段（商品代码首次出现之前的内容），只处理后面的分段 | 避免第一段无意义内容干扰数字提取 |
| `MID` + `REGEXEXTRACT("\d+")` | `REGEXEXTRACT("^\d+")` 取每段开头的数字 | 拆分后每段都以"商品代码后面的内容"开头，直接取段首数字即可 |

**执行逻辑**：假设物料详情 = `"abc G123 200 xyz G123 150 end"`，商品代码 = `G123`

1. `SPLIT("G123")` → `["abc ", " 200 xyz ", " 150 end"]`
2. `SLICE(1)` → `[" 200 xyz ", " 150 end"]`
3. 每段 `REGEXEXTRACT("^\d+")` → `200`, `150`
4. `VALUE` → `200`, `150`
5. 内层 `SUM()` → `350`
6. 外层对所有物料详情重复上述过程后 `SUM()`

抱歉，飞书多维表格没有 `SPLIT` 和 `SLICE`。正确思路是：**利用 `SUBSTITUTE` 的第 4 个参数（第几次出现）分别定位每次出现的商品代码**，各自提取后相加。

把原公式 MAP 内部的 `IF(...)` 整体改为：**第一次提取 + 第二次提取**，最小改动如下：

```formula
[物料映射勿动].FILTER(CurrentValue.[日期] >= TODAY() - 91)
  .[物料详情]
  .LISTCOMBINE()
  .UNIQUE()
  .MAP(
    /* 第一次出现（原逻辑，不变） */
    IF(
      FIND(SUBSTITUTE([商品代码], " ", ""), CurrentValue) > 0,
      VALUE(
        REGEXEXTRACT(
          MID(
            CurrentValue,
            FIND(SUBSTITUTE([商品代码], " ", ""), CurrentValue) + LEN(SUBSTITUTE([商品代码], " ", "")),
            LEN(CurrentValue)
          ),
          "\d+"
        )
      ),
      0
    )
    +
    /* 第二次出现（新增）：用 SUBSTITUTE 定位第 2 次出现，其余提取逻辑相同 */
    IF(
      FIND("◆", SUBSTITUTE(CurrentValue, SUBSTITUTE([商品代码], " ", ""), "◆", 2)) > 0,
      VALUE(
        REGEXEXTRACT(
          MID(
            SUBSTITUTE(CurrentValue, SUBSTITUTE([商品代码], " ", ""), "◆", 2),
            FIND("◆", SUBSTITUTE(CurrentValue, SUBSTITUTE([商品代码], " ", ""), "◆", 2)) + 1,
            LEN(CurrentValue)
          ),
          "\d+"
        )
      ),
      0
    )
  ).SUM()
```

**核心原理**：

| 步骤 | 说明 |
|---|---|
| `SUBSTITUTE(CurrentValue, code, "◆", 2)` | 把**第 2 次**出现的商品代码替换为特殊标记 `◆`（第 1 次不动） |
| `FIND("◆", ...)` | 定位第 2 次出现的位置 |
| `MID(..., FIND("◆")+1, ...)` | 从标记后面截取，`REGEXEXTRACT("\d+")` 提取数字 |
| 若只出现 1 次 | `SUBSTITUTE(..., 2)` 不做替换，`FIND("◆")` 返回 0，`IF` 返回 0，不影响结果 |

如果之后出现 3 次或更多，在末尾继续加 `+ IF(..., SUBSTITUTE(..., "◆", 3), ...)` 类推即可。

飞书多维表格的公式函数不支持全局多次匹配——`REGEXEXTRACT` 只返回第一个结果，没有 `SPLIT` / `TEXTSPLIT` / `REGEXREPLACE`（全局）这类"一次性搜到底"的能力。这是公式引擎本身的硬边界。

在这个约束下，两个务实路径：

**路径一：确定最大出现次数，硬编码到底**

如果物料详情里商品代码最多出现 3 次，就加 3 段 `SUBSTITUTE(..., "◆", N)`，本质上仍是"末尾加"，只是 N 封顶后就不用再加了。这是纯公式方案的上限。

**路径二：飞书脚本 / 自动化（真正"不限次数"）**

在飞书多维表格里加一个**脚本字段**或用**飞书集成自动化（JS/Python 节点）**，几行代码就解决：

```javascript

const code = [商品代码].replace(/\s/g, '');

const re = new RegExp(code + '.*?(\\d+)', 'g');
let m;
while ((m = re.exec([物料详情])) !== null) {
  sum += parseInt(m[1]);
}
return sum;
```
